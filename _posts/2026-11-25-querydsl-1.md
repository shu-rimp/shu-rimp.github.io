## QueryDSL을 쓰는 이유

JPQL은 문자열이라 오타나 잘못된 필드명이 있어도 실행해 보기 전까지 알 수 없습니다. QueryDSL은 쿼리를 자바 코드로 작성하기 때문에 이런 문제가 생깁니다.

- 문법 오류를 **컴파일 시점**에 잡을 수 있어 런타임 오류를 예방할 수 있습니다
- IDE 자동완성을 쓸 수 있습니다
- **동적 쿼리**를 편하게 작성할 수 있습니다
- 조건을 메서드로 작성해 **재사용**할 수 있습니다

---

## QueryDSL 설정

`build.gradle`에 의존성을 추가합니다. Spring Boot 3(jakarta) 기준 예시입니다.

```groovy
dependencies {
    implementation 'com.querydsl:querydsl-jpa:5.0.0:jakarta'
    annotationProcessor 'com.querydsl:querydsl-apt:5.0.0:jakarta'
    annotationProcessor 'jakarta.annotation:jakarta.annotation-api'
    annotationProcessor 'jakarta.persistence:jakarta.persistence-api'
}
```

엔티티를 만든 뒤 Gradle로 빌드하면 `build/generated` 아래에 **Q클래스**가 생성됩니다. QueryDSL은 이 Q클래스로 쿼리를 작성합니다. 생성된 Q클래스를 지우고 싶으면 `gradle clean`을 실행합니다.

> IntelliJ에서 빌드·실행 설정이 `IntelliJ IDEA`로 되어 있으면 Q클래스 import가 안 될 수 있습니다. 설정을 `Gradle`로 바꿔 주세요.

> 실제 쿼리에 바인딩된 파라미터 값을 로그로 보고 싶다면 `p6spy-spring-boot-starter`를 추가하면 됩니다. 로그 양이 많아 성능에 영향을 주므로 개발할 때만 사용합니다.

## JPAQueryFactory와 Q클래스

QueryDSL을 쓰려면 `JPAQueryFactory`와 Q클래스가 필요합니다. `select`, `from`, `where` 같은 SQL 구문을 메서드 체인으로 작성하고, `.eq()` 같은 메서드로 파라미터 바인딩도 자동으로 처리됩니다.

```java
@Autowired
EntityManager em;

JPAQueryFactory queryFactory;

@BeforeEach
void before() {
    queryFactory = new JPAQueryFactory(em);
}

@Test
void startQuerydsl() {
    Member findMember = queryFactory
            .select(member)
            .from(member)
            .where(member.username.eq("member1"))
            .fetchOne();
}
```

### Q클래스 사용 방법

```java
// 1. 별칭을 직접 지정해 생성
QMember m = new QMember("m");

// 2. Q클래스에 만들어진 static 필드 사용
QMember m = QMember.member;

// 2-1. static import 사용 (권장)
import static study.querydsl.entity.QMember.member;

queryFactory.select(member) // 바로 사용
```

| 방법               | 언제 쓰나                                                     |
| ------------------ | ------------------------------------------------------------- |
| `new QMember("m")` | 같은 엔티티를 별칭을 달리해 여러 번 써야 할 때 (예: 서브쿼리) |
| `QMember.member`   | 일반적인 경우                                                 |
| static import      | 가독성과 간결함을 위해 가장 권장                              |

> `QMember.member`는 `static final` 필드에 미리 생성해 둔 인스턴스를 참조하는 방식입니다. 매번 `new`로 생성하는 것보다 불필요한 객체 생성을 줄일 수 있습니다.

## 검색 조건

QueryDSL은 JPQL이 제공하는 검색 조건을 모두 제공합니다.

```java
member.username.eq("member1")      // username = 'member1'
member.username.ne("member1")      // username != 'member1'
member.username.eq("member1").not()
member.age.in(10, 20)
member.age.notIn(10, 20)
member.age.between(10, 30)
member.username.like("member%")
member.username.startsWith("member")
```

`where()` 안의 AND 조건은 `.and()`로 이어도 되지만, **쉼표로 나열**해도 AND로 처리됩니다.

```java
queryFactory
        .selectFrom(member)
        .where(
                member.username.eq("member1"),
                member.age.eq(10)
        )
        .fetch();
```

---

## 결과 조회

| 메서드           | 동작                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| `fetch()`        | 리스트 조회. 결과가 없으면 빈 리스트                                    |
| `fetchOne()`     | 단건 조회. 결과가 없으면 `null`, 둘 이상이면 `NonUniqueResultException` |
| `fetchFirst()`   | `limit(1).fetchOne()`과 같음                                            |
| `fetchResults()` | 페이징 정보와 total count를 함께 조회 (**deprecated**)                  |
| `fetchCount()`   | count 쿼리로 변경해 개수 조회 (**deprecated**)                          |

> `fetchResults()`와 `fetchCount()`는 QueryDSL 5.0부터 deprecated입니다. 단순히 select 절을 count로 바꿔 실행하는 방식이라, 조인이 많은 복잡한 쿼리에서는 정확하지 않거나 비효율적입니다. 실무에서는 count 쿼리와 조회 쿼리를 다르게 작성하는 경우가 많아서, **count 쿼리를 따로 작성해 `fetchOne()`으로 가져오는 방식**이 권장됩니다. 자세한 내용은 2편의 페이징에서 다룹니다.

## 정렬과 페이징

`orderBy()`로 정렬 조건을 지정하고, 쉼표로 여러 조건을 줄 수 있습니다. `asc()`, `desc()`와 함께 null 정렬 순서(`nullsLast()`, `nullsFirst()`)도 지정할 수 있습니다.

```java
queryFactory
        .selectFrom(member)
        .orderBy(member.age.desc(), member.username.asc().nullsLast())
        .fetch();
```

페이징은 `offset()`과 `limit()`으로 합니다. `offset`은 **0부터** 시작하고, 실제 SQL은 사용하는 데이터베이스의 방언에 맞춰 생성됩니다.

```java
queryFactory
        .selectFrom(member)
        .orderBy(member.username.desc())
        .offset(1)
        .limit(2)
        .fetch();
```

## 집합

`count`, `sum`, `avg`, `max`, `min` 같은 집계 함수를 제공합니다. 여러 값을 select하면 결과는 `List<Tuple>`로 반환되고, select 절에 썼던 표현식 그대로 값을 꺼낼 수 있습니다.

```java
List<Tuple> result = queryFactory
        .select(member.count(), member.age.sum(), member.age.avg())
        .from(member)
        .fetch();

Tuple tuple = result.get(0);
tuple.get(member.age.sum());
```

`groupBy()`와 `having()`도 지원합니다.

```java
queryFactory
        .select(team.name, member.age.avg())
        .from(member)
        .join(member.team, team)
        .groupBy(team.name)
        .fetch();
```

## 조인

첫 번째 파라미터에 조인 대상, 두 번째 파라미터에 별칭으로 사용할 Q타입을 지정합니다. `join`(inner), `leftJoin`, `rightJoin`을 모두 지원합니다.

```java
queryFactory
        .selectFrom(member)
        .join(member.team, team)
        .where(team.name.eq("teamA"))
        .fetch();
```

### 세타 조인

연관관계가 없는 필드끼리도 조인할 수 있습니다. `from()`에 조인할 Q타입을 나열합니다.

```java
queryFactory
        .select(member)
        .from(member, team)
        .where(member.username.eq(team.name))
        .fetch();
```

> 세타 조인은 두 테이블을 모두 조인한 뒤 where 절에서 걸러내는 방식이라 성능에 주의해야 합니다. 이 방식으로는 외부 조인이 안 되지만, 아래의 `on` 절을 쓰면 외부 조인도 가능합니다.

---

## 조인 on 절

`on` 절로 할 수 있는 일은 두 가지입니다.

1. 조인 대상 필터링
2. 연관관계 없는 엔티티 외부 조인

### 1. 조인 대상 필터링

회원은 모두 조회하면서, 팀은 이름이 `teamA`인 경우만 조인하는 예시입니다.

```sql
-- JPQL
select m, t from Member m left join m.team t on t.name = 'teamA'
```

```java
List<Tuple> result = queryFactory
        .select(member, team)
        .from(member)
        .leftJoin(member.team, team).on(team.name.eq("teamA"))
        .fetch();
```

> `on` 절로 조건을 거는 게 의미 있는 건 **외부 조인**일 때입니다. 내부 조인에서는 `on`에 조건을 걸든 `where`에 걸든 결과가 같으므로, 내부 조인이면 익숙한 `where` 절을 쓰는 게 낫습니다.

### 2. 연관관계 없는 엔티티 외부 조인

```java
List<Tuple> result = queryFactory
        .select(member, team)
        .from(member)
        .leftJoin(team).on(member.username.eq(team.name))
        .fetch();
```

일반 조인과 달리 `leftJoin()`에 엔티티 하나만 넣습니다. `leftJoin(member.team, team)`이면 연관관계(외래 키)로 조인하지만, `leftJoin(team)`은 `on` 절의 조건으로만 조인합니다.

## 페치 조인

일반 조인 문법 뒤에 `.fetchJoin()`을 붙이면 됩니다. 연관된 엔티티를 SQL 한 번에 함께 조회해 N+1 문제를 막을 때 씁니다.

```java
Member findMember = queryFactory
        .selectFrom(member)
        .join(member.team, team).fetchJoin()
        .where(member.username.eq("member1"))
        .fetchOne();
```

테스트에서 페치 조인이 적용됐는지는 `PersistenceUnitUtil.isLoaded()`로 확인할 수 있습니다. 연관 엔티티가 프록시가 아니라 **실제로 로딩됐는지**를 알려 줍니다.

```java
@PersistenceUnit
EntityManagerFactory emf;

boolean loaded = emf.getPersistenceUnitUtil().isLoaded(findMember.getTeam());
assertThat(loaded).as("페치 조인 적용").isTrue();
```

`as()`는 검증이 실패했을 때 보여 줄 설명입니다.

## 서브쿼리

`com.querydsl.jpa.JPAExpressions`로 서브쿼리를 작성합니다. 서브쿼리의 from 절에 바깥 쿼리와 같은 엔티티를 쓴다면 **별칭이 다른 Q타입**을 새로 만들어야 합니다.

```java
QMember memberSub = new QMember("memberSub");

// 나이가 가장 많은 회원 조회
List<Member> result = queryFactory
        .selectFrom(member)
        .where(member.age.eq(
                JPAExpressions
                        .select(memberSub.age.max())
                        .from(memberSub)
        ))
        .fetch();
```

서브쿼리는 select 절과 where 절에서 쓸 수 있지만, **from 절의 서브쿼리(인라인 뷰)는 지원하지 않습니다.** JPQL의 한계이기도 한데, Hibernate 6.1부터는 from 절 서브쿼리를 지원하지만 QueryDSL은 여전히 공식 지원하지 않습니다.

from 절 서브쿼리가 필요할 때의 대안은 다음과 같습니다.

- 조인으로 바꿀 수 있으면 조인으로 처리합니다
- 쿼리를 나눠 애플리케이션에서 여러 번 실행합니다. 복잡한 쿼리 한 방보다 나눠서 실행하는 편이 나을 때도 많습니다
- 네이티브 SQL을 사용합니다

## case 문

단순한 조건은 `when().then()`으로 씁니다.

```java
queryFactory
        .select(member.age
                .when(10).then("열살")
                .when(20).then("스무살")
                .otherwise("기타"))
        .from(member)
        .fetch();
```

범위 조건처럼 복잡한 경우에는 `CaseBuilder`를 씁니다.

```java
queryFactory
        .select(new CaseBuilder()
                .when(member.age.between(0, 20)).then("0~20살")
                .when(member.age.between(21, 30)).then("21~30살")
                .otherwise("기타"))
        .from(member)
        .fetch();
```

> 복잡한 데이터 가공은 데이터베이스보다 애플리케이션에서 처리하는 게 일반적으로 낫습니다. DB에서는 데이터를 최소한으로 필터링·그룹핑해서 가져오는 데 집중합니다.

## 상수와 문자 더하기

상수는 `Expressions.constant()`, 문자열 연결은 `concat()`을 씁니다. 문자가 아닌 타입(숫자, enum 등)을 연결할 때는 `stringValue()`로 문자로 바꿔야 합니다.

```java
queryFactory
        .select(member.username.concat("_").concat(member.age.stringValue()))
        .from(member)
        .fetch();
// 결과 예: member1_10
```
